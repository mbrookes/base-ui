# Chat: Conversation list

<Subtitle>Render a sidebar listing all conversations and let users switch between them, with cursor-based history pagination.</Subtitle>
<Meta
  name="description"
  content="Build a multi-conversation inbox sidebar with Base UI Chat's ChatConversationList components and history loading."
/>

Use `ChatConversationList` together with `ChatConversation` inside `Chat.Layout` to build a two-pane inbox.

## Anatomy

```tsx
import { Chat } from '@base-ui/react/chat';
import { ChatConversationList } from '@base-ui/react/chat-conversation-list';
import { ChatConversation } from '@base-ui/react/chat-conversation';

<Chat.Root
  adapter={adapter}
  conversations={conversations}
  activeConversationId={activeConversationId}
  onActiveConversationChange={setActiveConversationId}
>
  <Chat.Layout>
    <ChatConversationList.Root pane="conversations">
      {conversationIds.map((id) => (
        <ChatConversationList.Item key={id} conversationId={id}>
          <ChatConversationList.ItemAvatar />
          <ChatConversationList.ItemContent>
            <ChatConversationList.Title />
            <ChatConversationList.Preview />
          </ChatConversationList.ItemContent>
          <ChatConversationList.Timestamp />
          <ChatConversationList.UnreadBadge />
        </ChatConversationList.Item>
      ))}
    </ChatConversationList.Root>

    <ChatConversation.Root pane="thread">
      <ChatConversation.Header>
        <ChatConversation.Title />
      </ChatConversation.Header>

      <ChatMessageList.Root renderItem={/* ... */}>
        <ChatMessageList.Viewport>
          <ChatMessageList.Content />
        </ChatMessageList.Viewport>
      </ChatMessageList.Root>

      <ChatComposer.Root>
        <ChatComposer.TextArea />
        <ChatComposer.Toolbar>
          <ChatComposer.SendButton />
        </ChatComposer.Toolbar>
      </ChatComposer.Root>
    </ChatConversation.Root>
  </Chat.Layout>
</Chat.Root>
```

`Chat.Layout` is a CSS Grid container that positions the `conversations` and `thread` panes side by side.
Pass `pane="conversations"` to `ChatConversationList.Root` and `pane="thread"` to `ChatConversation.Root` to wire each component into the correct grid area.

## Conversations data

Provide conversations through the `conversations` prop on `Chat.Root`.
Each conversation is a `ChatConversation` object:

```ts
interface ChatConversation {
  id: string;
  title?: string;
  subtitle?: string;
  unreadCount?: number;
  readState?: 'read' | 'unread';
  lastMessageAt?: string; // ISO 8601
  participants?: ChatUser[];
  metadata?: Record<string, unknown>;
}
```

Control the active conversation with `activeConversationId` and `onActiveConversationChange`:

```tsx
const [activeId, setActiveId] = React.useState(conversations[0].id);

<Chat.Root
  adapter={adapter}
  conversations={conversations}
  activeConversationId={activeId}
  onActiveConversationChange={(nextId) => {
    if (nextId) setActiveId(nextId);
  }}
>
```

`onActiveConversationChange` receives `string | undefined` — it fires with `undefined` when the active conversation is cleared, so guard before assigning to non-nullable state.

## Data attributes

`ChatConversationList.Item` exposes data attributes for styling:

| Attribute              | When present                                          |
| :--------------------- | :---------------------------------------------------- |
| `data-conversation-id` | Always present, value is the conversation ID          |

The item tracks `selected`, `unread`, and `focused` states through the component's `State` interface.
Style these states by targeting the component's `render` prop or using the `className` callback:

```tsx
<ChatConversationList.Item
  key={id}
  conversationId={id}
  className={({ selected, unread }) =>
    `item ${selected ? 'item--selected' : ''} ${unread ? 'item--unread' : ''}`
  }
>
```

## Variant

`ChatConversationList.Root` accepts a `variant` prop:

- `'default'` (default) — shows avatar, title, preview, timestamp, and unread badge.
- `'compact'` — shows only an unread indicator dot, the title, and an actions slot.

```tsx
<ChatConversationList.Root variant="compact" pane="conversations">
  {/* ... */}
</ChatConversationList.Root>
```

## Keyboard navigation

`ChatConversationList.Root` manages roving focus over items:

| Key                   | Action                               |
| :-------------------- | :----------------------------------- |
| <kbd>ArrowUp</kbd>    | Move focus to the previous item      |
| <kbd>ArrowDown</kbd>  | Move focus to the next item          |
| <kbd>Home</kbd>       | Move focus to the first item         |
| <kbd>End</kbd>        | Move focus to the last item          |
| <kbd>Enter</kbd>      | Select the focused conversation      |

Only one item is in the tab order at a time.
The focused item carries `tabIndex={0}` and all others `tabIndex={-1}`.
Selected items receive `aria-current="true"`.

## Loading message history

Implement `listMessages` on your adapter to load a conversation's history when it becomes active.
The runtime calls it automatically when `activeConversationId` changes:

```ts
const adapter: ChatAdapter = {
  async sendMessage(input) { /* ... */ },

  async listMessages({ conversationId, cursor }) {
    const params = new URLSearchParams({ cursor: cursor ?? '' });
    const res = await fetch(`/api/conversations/${conversationId}/messages?${params}`);
    const { messages, nextCursor, hasMore } = await res.json();
    return { messages, cursor: nextCursor, hasMore };
  },
};
```

`listMessages` receives `{ conversationId, cursor, direction }` and returns `{ messages, cursor, hasMore }`.

| Parameter     | Description                                                  |
| :------------ | :----------------------------------------------------------- |
| `cursor`      | Opaque pagination cursor; `undefined` on the first page     |
| `hasMore`     | Set `true` when more pages exist; defaults to `false`       |

## Cursor-based pagination

The adapter interface is generic over the cursor type.
The default is `string`, which works for opaque server tokens and ISO timestamps.
For structured cursors, provide the type explicitly:

```ts
interface MyCursor {
  page: number;
  token: string;
}

const adapter: ChatAdapter<MyCursor> = {
  async sendMessage(input) { /* ... */ },

  async listMessages({ cursor }) {
    const page = cursor?.page ?? 1;
    const res = await fetch(`/api/messages?page=${page}`);
    const { messages, nextPage, token } = await res.json();
    return {
      messages,
      cursor: { page: nextPage, token },
      hasMore: !!nextPage,
    };
  },
};
```

## Tracking pagination state

Read history loading state from `useChatStatus()`:

```tsx
import { useChatStatus } from '@base-ui/react/chat';

function HistoryOverlay() {
  const { hasMoreHistory, isLoadingHistory } = useChatStatus();

  if (!isLoadingHistory) return null;
  return (
    <ChatMessageList.Overlay>
      <div role="status" aria-label="Loading older messages" />
    </ChatMessageList.Overlay>
  );
}
```

| Field              | Type      | Description                                               |
| :----------------- | :-------- | :-------------------------------------------------------- |
| `hasMoreHistory`   | `boolean` | Whether more pages are available                          |
| `isLoadingHistory` | `boolean` | Whether a history fetch is currently in flight            |

Trigger a manual history load with `loadMoreHistory()` from `useChatActions()`:

```tsx
import { useChatActions } from '@base-ui/react/chat';

function LoadMoreButton() {
  const { loadMoreHistory } = useChatActions();
  const { hasMoreHistory } = useChatStatus();

  if (!hasMoreHistory) return null;
  return (
    <button onClick={() => loadMoreHistory()}>Load earlier messages</button>
  );
}
```

Scroll-triggered history loading happens automatically when the user scrolls to the top of `ChatMessageList.Root`.

## Error handling

When `listMessages` throws, the runtime records a `ChatError` with `source: 'history'`:

```tsx
<Chat.Root
  adapter={adapter}
  onError={(error) => {
    if (error.source === 'history') {
      console.error('Failed to load message history:', error.message);
    }
  }}
>
```
