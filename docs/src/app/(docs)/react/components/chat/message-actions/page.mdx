# Chat: Message actions

<Subtitle>Reveal per-message action buttons on hover or focus for copy, retry, regenerate, and custom operations.</Subtitle>
<Meta
  name="description"
  content="Add per-message action buttons to Base UI Chat with hover-revealed toolbars."
/>

`ChatMessage.Actions` renders an action toolbar that you populate with buttons.
Pair it with CSS to reveal the bar on hover or keyboard drill-in.

## Anatomy

Add `ChatMessage.Actions` inside `ChatMessage.Root`:

```tsx
import { ChatMessage } from '@base-ui/chat/chat-message';

<ChatMessage.Root messageId={id}>
  <ChatMessage.Avatar />
  <ChatMessage.Content />
  <ChatMessage.Meta />
  <ChatMessage.Actions>
    <CopyButton />
    <RetryButton />
  </ChatMessage.Actions>
</ChatMessage.Root>
```

`ChatMessage.Actions` renders a `<div role="toolbar">` with an accessible label.
Place any action buttons you want as children.

## Visibility behavior

The action bar is hidden by default and becomes visible when:

- The user hovers over the parent `ChatMessage.Root` row
- The user drills into the focused message with <kbd>Enter</kbd> (the message row receives `data-actionable`)
- Focus is inside the action bar itself (`:focus-within`)

Implement the reveal in CSS:

```css
.message-actions {
  opacity: 0;
  visibility: hidden;
  transition: opacity 150ms;
}

.message-row:hover .message-actions,
.message-row[data-actionable] .message-actions,
.message-actions:focus-within {
  opacity: 1;
  visibility: visible;
}

@media (prefers-reduced-motion: reduce) {
  .message-actions {
    transition: none;
  }
}
```

Using `visibility: hidden` removes the action buttons from the tab order when not visible, so keyboard users can tab through the chat without stopping on invisible controls.

## Accessing message context

Use `useMessage(id)` to read the current message and conditionally render actions per role:

```tsx
import { useMessage, useChatActions } from '@base-ui/chat/chat';

function MessageActionBar({ messageId }: { messageId: string }) {
  const message = useMessage(messageId);
  const { retry, regenerate } = useChatActions();

  if (!message) return null;

  return (
    <>
      <CopyButton text={message.parts.find(p => p.type === 'text')?.text ?? ''} />
      {message.role === 'user' && message.status === 'error' && (
        <button onClick={() => retry(messageId)}>Retry</button>
      )}
      {message.role === 'assistant' && (
        <button onClick={() => regenerate(messageId)}>Regenerate</button>
      )}
    </>
  );
}
```

`useChatActions()` returns the stable runtime actions object — it does not subscribe to message state, so the toolbar does not re-render on every streaming token.

## `useChatActions` reference

`useChatActions()` returns all runtime actions without triggering re-renders on state changes:

```ts
import { useChatActions } from '@base-ui/chat/chat';

const actions = useChatActions();
```

| Action                    | Description                                         |
| :------------------------ | :-------------------------------------------------- |
| `sendMessage(input)`      | Send a new user message                             |
| `stopStreaming()`         | Cancel the active stream                            |
| `retry(messageId)`        | Re-send the failed user message                     |
| `regenerate(messageId)`   | Request a fresh assistant reply                     |
| `setActiveConversation(id)` | Switch to a different conversation               |
| `loadMoreHistory()`       | Load earlier messages                               |
| `setError(error)`         | Manually set or clear the global error              |
| `addToolApprovalResponse(input)` | Approve or deny a pending tool call        |

## Dropdown actions menu

For more complex action sets, use the `ChatMessageActionsMenu` components to build a dropdown:

```tsx
import {
  ChatMessageActionsMenu,
  ChatMessageActionsMenuTrigger,
  ChatMessageActionsMenuPositioner,
  ChatMessageActionsMenuPopup,
  ChatMessageActionsMenuGroup,
  ChatMessageActionsMenuGroupLabel,
  ChatMessageActionsMenuItem,
} from '@base-ui/chat/chat-message';

function MessageDropdownMenu({ messageId }: { messageId: string }) {
  const { retry, regenerate } = useChatActions();

  return (
    <ChatMessageActionsMenu>
      <ChatMessageActionsMenuTrigger>
        <button aria-label="More actions">⋯</button>
      </ChatMessageActionsMenuTrigger>
      <ChatMessageActionsMenuPositioner>
        <ChatMessageActionsMenuPopup>
          <ChatMessageActionsMenuGroup>
            <ChatMessageActionsMenuGroupLabel>Actions</ChatMessageActionsMenuGroupLabel>
            <ChatMessageActionsMenuItem onClick={() => retry(messageId)}>
              Retry
            </ChatMessageActionsMenuItem>
            <ChatMessageActionsMenuItem onClick={() => regenerate(messageId)}>
              Regenerate
            </ChatMessageActionsMenuItem>
          </ChatMessageActionsMenuGroup>
        </ChatMessageActionsMenuPopup>
      </ChatMessageActionsMenuPositioner>
    </ChatMessageActionsMenu>
  );
}
```

## Copy to clipboard

A common action is copying the message text. Read the text parts from the message and write them to the clipboard:

```tsx
import { useMessage } from '@base-ui/chat/chat';

function CopyButton({ messageId }: { messageId: string }) {
  const message = useMessage(messageId);
  const [copied, setCopied] = React.useState(false);

  const handleCopy = async () => {
    const text = message?.parts
      .filter((p) => p.type === 'text')
      .map((p) => p.text)
      .join('\n') ?? '';
    await navigator.clipboard.writeText(text);
    setCopied(true);
    setTimeout(() => setCopied(false), 2000);
  };

  return (
    <button onClick={handleCopy} aria-label={copied ? 'Copied' : 'Copy'}>
      {copied ? '✓' : 'Copy'}
    </button>
  );
}
```

## Data attributes

`ChatMessage.Actions` inherits the message owner state and exposes data attributes for styling:

| Attribute          | When present                        |
| :----------------- | :---------------------------------- |
| `data-own-message` | The message belongs to the local user |
| `data-grouped`     | The message is grouped (not first in a run) |
